س11. من أين يأتي Cache-Control: no-store, no-cache, must-revalidate؟
--------------------------------------------------------------------
**PHP** عندما تكون **DISABLE_HTML_CACHE** في **.env.php** مفعّلة: **orange_send_html_no_cache_headers()** في **config.php** (تُستدعى من **includes/header.php** و**admin/index.php** و**admin/login.php** و**admin/preview-storefront.php**) — للـ **HTML** فقط. **أصول ثابتة** (.css، .js، صور، خطوط): قالب **web.config.example** — قاعدة **OrangeStaticCacheAssets** تضبط **public, max-age=2592000** لطلبات الملفات المطابقة فقط؛ **allowedServerVariables** لـ **RESPONSE_Cache-Control** على IIS.

س12. عندما يطلب المالك «يُولَّد تلقائياً» أو «لا يُسمح بالتعديل اليدوي» — أي ستايل في الأدمن؟
--------------------------------------------------------------------
**قرار مالك (اتفاق مع الوكيل):** إن قال المالك إن الحقل **يُولَّد أوتوماتيكاً** أو **لا يسمح بالتعديل اليدوي داخله**، يلزم الوكيل تطبيق **الطبقة المموّهة** على الحقل في الأدمن:
- لعنصر **`input`** (أو حقل يشبهه): الصنفان **`admin-sort-field`** و **`admin-sort-field--muted`** مع **`readonly`** أو **`disabled`** حسب السلوك المطلوب؛ التعريف في **`admin/assets/admin.css`** (خلفية فاتحة **`#f4f6f9`**، مؤشر **`default`**، وتعديلات لـ **`readonly`/`disabled`**).
- لخلية **جدول** (ليست `input`) **فقط إذا طلب المالك ذلك صراحةً** لعمود عرض فقط: نفس **اللون البصري** (مثلاً **`#f4f6f9`**) أو صنف محلي؛ **لا** يُفترض تلوين أعمدة الجداول تلقائياً مع خانات النماذج (مثال: **فروع الشجرة الموحّدة** — الطبقة المموّهة لـ **`slug`** في **الكروت الثلاث** فقط ما لم يُذكر العكس).
**ملاحظة:** للحقول المموّهة **القابلة للكتابة** (نادر) يُضبط **`cursor: text`** محلياً إن لزم حتى لا يُضلِل المستخدم.


--------------------------------------------------------------------
س13. قبل رفع أي تعديل على main — كيف تتأكد أن الشاشة لا تظهر فاضية؟
--------------------------------------------------------------------
**إلزام (قرار المالك):** لا يُرفع تعديل على `main` إلا بعد التحقق أن الشاشة
المعدّلة **تعرض محتواها كاملاً** (ليست فاضية):

1. شغّل الصفحة محلياً أو عبر curl بعد التعديل.
2. تأكد أن HTML الناتج يحتوي على المحتوى المتوقع (النماذج / الأزرار / الـ JS).
3. لو الصفحة فاضية أو فيها HTML ناقص = خطأ PHP صامت = **لا ترفع**.
4. السبب الشائع: استدعاء دالة ترمي RuntimeException (مثل فحص حساب غير صالح
   أو عمود غير موجود) — تأكد أن المنطق الجديد لا يفترض بيانات قد لا تكون موجودة
   على كل البيئات.
5. **إلزام إضافي:** بعد الرفع، افتح الشاشة فعلياً في المتصفح (أو عبر computerUse)
   وتأكد أن التعديلات تظهر بشكل صحيح — لا يكفي PHP lint أو curl وحده؛ يجب رؤية
   النتيجة النهائية كما يراها المستخدم.

س15. سياق التطوير الجاري — إعادة بناء نظام العملاء (اتفاقات المالك 2026-05-17)
--------------------------------------------------------------------
**الحالة:** مرحلة التخطيط — اتفاقات مُثبّتة، لم يبدأ التنفيذ.

**1) رؤية عامة:**
- **كل عميل** (سواء سجّل من الموقع أو ما اشتراش أو سجّله الأدمن أو اشترى كضيف) = يظهر بشاشة العملاء بالأدمن + ياخد كود تسلسلي تلقائي
- **المعرّف الفريد** = رقم الهاتف (E.164) — UNIQUE على `customers.phone`
- **الكود** = تسلسلي تلقائي (مثل الموردين)

**2) أنواع العملاء محاسبياً (حسابات مجمّعة بالدليل):**
- حساب **عملاء أونلاين** ← كل فواتير الأونلاين
- حساب **عملاء نقدي** ← كل فواتير الكاش (أدمن)
- حساب **عملاء آجل** ← كل فواتير الآجل (أدمن)
- **العميل ما بيتربطش بحساب فردي بالشجرة** (بعكس المورد) — الحساب المجمّع هو اللي بيظهر بالدليل
- نفس العميل ممكن يكون له حركات على **أكثر من حساب مجمّع** (حسب نوع كل فاتورة)

**3) كشف حساب العميل:**
- يبيّن **كل** حركاته (نقدي + آجل + أونلاين) بالتفصيل (رقم طلب + مبلغ + تاريخ + **نوع الفاتورة**)
- مصدر البيانات: `party_subledger` (حركة لكل فاتورة باسم العميل)
- النقدي يظهر (دخل وخرج) — لمعرفة حجم التعامل ولسياسات العروض المستقبلية
- شاشة كشف الحساب = **صفحة منفصلة موحّدة** (نفس الصفحة لكشف المورد + العميل + أي حساب بالشجرة) = `partner_account_statement.php`

**4) توقيت القيد المحاسبي + التسجيل بكشف الحساب:**
- عميل أونلاين: **بعد التسليم** (عند `completed`)
- عميل نقدي (أدمن): **بعد التسليم** (عند `completed`) — بسبب الدليفري
- عميل آجل (أدمن): **بعد التسليم** (عند `completed`) — نفس السبب
- **الحكمة:** البيع عن طريق الدليفري = ما يُسجّل محاسبياً إلا بعد تأكيد التسليم

**5) العميل المسجّل من الموقع (ما اشتراش):**
- **تلقائياً** لحظة التسجيل بالموقع → ينزل بجدول `customers` + ياخد كود تسلسلي
- يظهر بشاشة العملاء بالأدمن (كشف حسابه فاضي)

**6) حد الائتمان:**
- يبقى كما هو — الأدمن يحدده لكل عميل بناءً على رؤيته
- يُطبّق فقط على الفواتير الآجلة

**7) الأقساط الشهرية (فاتورة مبيعات نقدي من الأدمن):**
- المالك سيوضّح لاحقاً — **لم يُحدّد بعد**

**8) شاشة كشف الحساب الموحّدة:**
- `partner_account_statement.php` — محتاج مراجعة هل تدعم البحث بالعملاء + الموردين + أي حساب بالشجرة
- المطلوب: شاشة واحدة أقدر أبحث فيها عن أي حساب أو عميل أو مورد

**9) ثغرات مطلوب إصلاحها:**
- إضافة `delivery_area_id` لجدول `customers` + تحويل حقل المنطقة بالأدمن لقائمة
- مزامنة `storefront_accounts` → `customers` تلقائياً عند التسجيل
- إثراء `orange_ensure_customer()` بنقل كل البيانات (منطقة/عنوان/بريد) من الطلب
- ربط FK بين `customers` و `storefront_accounts`

**الخطوة القادمة للوكيل التالي:**
1. اقرأ بند س15 كاملاً
2. راجع `partner_account_statement.php` — هل تدعم عميل + مورد + حساب شجرة؟
3. عدّل التسجيل بالموقع ليُنزل العميل تلقائياً بجدول `customers`
4. عدّل شاشة العملاء (المنطقة → قائمة + delivery_area_id)
5. تأكد أن كل فاتورة (نقدي/آجل/أونلاين) تسجّل حركة بـ `party_subledger` باسم العميل (بعد التسليم)
6. الأقساط — تنتظر توضيح المالك

س16. تحسين شاشة الميزانية العمومية (قرار المالك — تنفيذ 2026-05-20)
--------------------------------------------------------------------
**الحالة:** منفّذ في الكود — شاشة مستقلة + ملخص في التقارير المالية.

**المشكلة:** قسم «الميزانية العمومية (مبسطة)» داخل `financial_report.php` كان إجماليات فقط (أصول / خصوم / حقوق) بلا أسطر حسابات ولا تاريخ «حتى» ولا طباعة مثل «أرباح وخسائر».

**المطلوب (منفّذ):**

س17. تقارير المخزن الاحترافية (6 تقارير)
--------------------------------------------------------------------
**الحالة:** منفّذ (مرحلة أولى 2026-06-03) — شاشة موحّدة + كارت صنف محسّن؛ تبقى تحسينات تفصيلية (انظر «الفجوات» أسفل البند).

**المشكلة:** تقارير المخزن الحالية ضعيفة جداً — لا يوجد كارت صنف ولا تقارير تحليلية.

**المطلوب — 6 تقارير احترافية:**

**1) كارت الصنف (حركة صنف/متغير):**
- اختيار: صنف أو متغير (لون/مقاس) محدد
- فلتر: من تاريخ → إلى تاريخ
- يعرض: كل الحركات (مشتريات / مبيعات / مردود مشتريات / مردود مبيعات / تسويات)
- لكل حركة: التاريخ + نوع الحركة + المرجع (رقم فاتورة/طلب) + وارد + صادر + الرصيد التراكمي
- رصيد أول المدة + حركات الفترة + رصيد آخر المدة

**2) تقرير الجرد (أرصدة المخزون):**
- كل الأصناف/المتغيرات مع الرصيد الحالي
- فلتر: قسم / فئة (اختياري)
- الأعمدة: كود الصنف + الاسم + اللون + المقاس + الكمية المتاحة + التكلفة + القيمة (كمية × تكلفة)
- إجمالي قيمة المخزون بالأسفل

**3) تقرير أصناف بطيئة الحركة:**
- أصناف لم يحصل عليها حركة (بيع أو شراء) خلال فترة محددة (مثلاً 30/60/90 يوم)
- فلتر: عدد الأيام بدون حركة
- الأعمدة: الصنف + آخر حركة + الرصيد الحالي + التكلفة + القيمة المحجوزة

**4) تقرير إعادة الطلب (أصناف وصلت الحد الأدنى):**
- أصناف رصيدها ≤ حد إعادة الطلب (أو `orange_stock_low_alert_threshold`)
- الأعمدة: الصنف + الرصيد الحالي + الحد الأدنى + الفرق + آخر مورد

**5) تقرير قيمة المخزون:**
- ملخص: إجمالي قيمة المخزون (كمية × تكلفة لكل متغير)
- تفصيل: حسب القسم / الفئة
- مقارنة: السنة الحالية vs السابقة (اختياري)

**6) تقرير حركة المخزون الإجمالي:**
- فترة: من تاريخ → إلى تاريخ
- ملخص: إجمالي الوارد (مشتريات) + إجمالي الصادر (مبيعات) + المردود + التسويات
- تفصيل: لكل صنف (الوارد / الصادر / الصافي)

**شكل كل التقارير (موحّد):**
- هيدر: شعار الشركة + اسم الشركة + عنوان التقرير + الفترة/التاريخ
- جسم: جدول بيانات مع مجاميع فرعية وإجمالي
- فوتر: نص قانوني (اختياري) + رقم الصفحة
- زر طباعة
- تنسيق احترافي (مثل تقارير مكاتب التدقيق)

**مصدر البيانات:**
- `product_variants.stock_quantity` — الرصيد الحالي
- `stock_movements` — حركات المخزون (نوع + تاريخ + كمية + مرجع)
- `products` + `product_variants` — بيانات الصنف
- `purchases` + `purchase_items` — المشتريات
- `orders` + `order_items` — المبيعات
