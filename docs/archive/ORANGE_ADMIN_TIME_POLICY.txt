ORANGE — سياسة الوقت المركزية للإدمن (Admin Time Policy)
================================================================================
المسار: docs/archive/ORANGE_ADMIN_TIME_POLICY.txt
تاريخ القرار: 2026-07-25
آخر تحديث: 2026-07-25 (Phase 2 — Admin Orders / Payments DATETIME paths)
الحالة: Phase 1 foundation + Phase 2 partial migration (انظر خامساً-ب)

الغرض
-------
تثبيت قرار المالك النهائي لسياسة الوقت في شاشات الإدمن، وتوثيق عقود الأساس المركزي
في `includes/admin_time.php` دون تغيير سلوك الشاشات الحالية في هذه المرحلة.


--------------------------------------------------------------------
أولاً: قرار المالك (نهائي)
--------------------------------------------------------------------
1. السوبر أدمن يختار الدولة من **Current Country Context**.
2. شاشات الإدمن التابعة للدولة المختارة يجب (عند الترحيل لاحقاً) أن تعرض الوقت حسب
   **IANA** المخزّن في إعدادات الدولة (`countries.timezone`)، مثل:
   - Kuwait → Asia/Kuwait
   - Egypt → Africa/Cairo
3. اختيار الدولة يغيّر سياق الوقت داخل **جلسة الإدمن فقط**.
4. ممنوع تغيير ساعة/Timezone السيرفر عند تغيير الدولة.
5. ممنوع الاعتماد على Timezone جهاز الإدمن أو المتصفح كمرجع.
6. كل **لحظة حقيقية** (Absolute Moment) — إنشاء طلب، دفع، مخزون، قيد، Audit — مرجعها
   الداخلي **UTC** (ISO-8601 مع offset/Z عند النقل).
7. عند العرض تُحوَّل اللحظة إلى توقيت الدولة المالكة للسجل أو دولة السياق في الشاشة
   المفلترة بهذه الدولة.
8. معاني «اليوم / أمس / بداية اليوم / نهاية اليوم / التاريخ الافتراضي / الفلاتر اليومية»
   تُحسب حسب توقيت الدولة (IANA)، وليس UTC وحده ولا جهاز المستخدم — عند ترحيل الشاشات.
9. **Date-only** (مثل تاريخ ميلاد أو تاريخ مستند بلا ساعة) **لا** يخضع لتحويل Timezone.
10. **Business Local Time** (Delivery Slots، ساعات العمل) نوع دلالي منفصل — لا يُعامل
    تلقائياً كـ UTC Timestamp.
11. في شاشة متعددة الدول: استخدم Timezone **دولة السجل** صراحة عند الحاجة.


--------------------------------------------------------------------
ثانياً: أنواع دلالية (لا تُخلط)
--------------------------------------------------------------------
A) Absolute Moment — لحظة عالمية واحدة → تخزين/نقل UTC → عرض عبر IANA الدولة.
B) Date-only — قيمة Y-m-d تقويمية → بلا تحويل منطقة زمنية.
C) Country Local Business Time — ساعة جدارية للدولة (slots/hours) → ليست Absolute Moment.


--------------------------------------------------------------------
ثالثاً: Current Country Context
--------------------------------------------------------------------
- مصدر العرض الافتراضي للإدمن: `orange_admin_context_timezone($pdo)` /
  `orange_admin_time_timezone_for_admin_context($pdo)`.
- المصدر الوحيد للـ IANA: عمود `countries.timezone` (Country Configuration).
- لا خريطة code→timezone ثابتة في التطبيق كمرجع تشغيل.
- إن غاب/بطل IANA: خطأ إعدادات واضح (`OrangeAdminTimeConfigException`) — بلا اختراع
  Asia/Kuwait صامت، وبلا Browser TZ.


--------------------------------------------------------------------
رابعاً: Freeze — Backup Center و Restore Center
--------------------------------------------------------------------
**خارج نطاق ترحيل سياسة الوقت هذه.** تبقى مسارات الوقت الحالية في Backup/Restore
كما هي (عرضها الخاص، `generated_at` UTC، تنسيق JS الصفحة، …).
Phase 1 **لا** تستبدل دوالهما ولا تغيّر ملفاتهما.


--------------------------------------------------------------------
خامساً: Phase 1 — ما تم / ما لم يتم
--------------------------------------------------------------------
تم:
- أساس مركزي: `includes/admin_time.php`
- إتاحته عبر `includes/admin_page_bootstrap.php` (تحميل فقط — بلا تغيير شاشات)
- اختبار ذاتي معزول: `scripts/self_test_admin_time_foundation.php`
- هذا الملف الأرشيفي

لم يتم (بعد Phase 1):
- ترحيل شاشات المبيعات/المشتريات/المخزون/المحاسبة/التقارير/Audit/العملاء
- تعديل Storefront أو منطق الطلبات/المدفوعات
- تغيير `date_default_timezone_set` أو `SET time_zone` في `db()`
- Migration بيانات أو Schema revision من أجل هذه السياسة


--------------------------------------------------------------------
خامساً-ب: Phase 2 — Admin Orders + Payments (2026-07-25)
--------------------------------------------------------------------
النطاق: طلبات الإدمن + أحداث الحالة (عبر تحديث الحالة) + واجهة مراجعة المدفوعات.

ما تم ترحيله (Absolute Moment → كتابة UTC صريحة في أعمدة DATETIME):
- `orders.created_at` عند الإنشاء اليدوي: `admin/api/orders/create-manual.php`
- `orders.updated_at` / `orders.completed_at` عند:
  update / update-status / bulk-update-status / cancel-from-delivery /
  handover-to-agent / `includes/invoice_edit_helpers.php` (مسار تعديل فاتورة الإدمن)
- `orders.document_date` (Date-only): اليوم المحلي لدولة الطلب عبر IANA الدولة
- العرض: قائمة الطلبات، فاتورة الإدمن، قائمة «إنشاء قيود التسليم» —
  عبر `orange_admin_time_display_mysql_utc_or_dash` + `country_id` للسجل
- فلاتر من/إلى في `online_orders_final_posting.php`: حدود اليوم المحلي لسياق الدولة → UTC
  (`start <= completed_at < end_exclusive`)
- API مراجعة الدفع: حقل `created_at_display` للطلب (DATETIME)؛ الحقول TIMESTAMP تبقى raw

BLOCKER — لم يُرحَّل (يحتاج قرار Owner: Schema أو MySQL session UTC):
- `orders.paid_at` TIMESTAMP + `paid_at = NOW()` في `includes/payments/payment_core.php`
  (ملف مشترك مع Storefront؛ TIMESTAMP يعتمد على `SET time_zone = '+03:00'`)
- `payment_transactions.created_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP
- `order_intake_queue.created_at` / `updated_at` TIMESTAMP
- لا Data Migration؛ لا تغيير Schema؛ لا تغيير `date_default_timezone_set` / session TZ

مجمّد كما هو: Backup Center / Restore Center.
