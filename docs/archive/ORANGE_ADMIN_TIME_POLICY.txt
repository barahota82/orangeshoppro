ORANGE — سياسة الوقت المركزية للإدمن (Admin Time Policy)
================================================================================
المسار: docs/archive/ORANGE_ADMIN_TIME_POLICY.txt
تاريخ القرار: 2026-07-25
آخر تحديث: 2026-07-25 (Phase 2 / Step 3 — Inventory & Warehouses time)
الحالة: Phase 1 + Phase 2 Step 1 و Step 2 و Step 3 مغلقة (انظر خامساً-ب/ج/د/هـ)

الغرض
-------
تثبيت قرار المالك النهائي لسياسة الوقت في شاشات الإدمن، وتوثيق عقود الأساس المركزي
في `includes/admin_time.php` دون تغيير سلوك الشاشات الحالية في هذه المرحلة.


--------------------------------------------------------------------
أولاً: قرار المالك (نهائي)
--------------------------------------------------------------------
1. السوبر أدمن يختار الدولة من **Current Country Context**.
2. شاشات الإدمن التابعة للدولة المختارة يجب (عند الترحيل لاحقاً) أن تعرض الوقت حسب
   **IANA** المخزّن في إعدادات الدولة (`countries.timezone`)، مثل:
   - Kuwait → Asia/Kuwait
   - Egypt → Africa/Cairo
3. اختيار الدولة يغيّر سياق الوقت داخل **جلسة الإدمن فقط**.
4. ممنوع تغيير ساعة/Timezone السيرفر عند تغيير الدولة.
5. ممنوع الاعتماد على Timezone جهاز الإدمن أو المتصفح كمرجع.
6. كل **لحظة حقيقية** (Absolute Moment) — إنشاء طلب، دفع، مخزون، قيد، Audit — مرجعها
   الداخلي **UTC** (ISO-8601 مع offset/Z عند النقل).
7. عند العرض تُحوَّل اللحظة إلى توقيت الدولة المالكة للسجل أو دولة السياق في الشاشة
   المفلترة بهذه الدولة.
8. معاني «اليوم / أمس / بداية اليوم / نهاية اليوم / التاريخ الافتراضي / الفلاتر اليومية»
   تُحسب حسب توقيت الدولة (IANA)، وليس UTC وحده ولا جهاز المستخدم — عند ترحيل الشاشات.
9. **Date-only** (مثل تاريخ ميلاد أو تاريخ مستند بلا ساعة) **لا** يخضع لتحويل Timezone.
10. **Business Local Time** (Delivery Slots، ساعات العمل) نوع دلالي منفصل — لا يُعامل
    تلقائياً كـ UTC Timestamp.
11. في شاشة متعددة الدول: استخدم Timezone **دولة السجل** صراحة عند الحاجة.


--------------------------------------------------------------------
ثانياً: أنواع دلالية (لا تُخلط)
--------------------------------------------------------------------
A) Absolute Moment — لحظة عالمية واحدة → تخزين/نقل UTC → عرض عبر IANA الدولة.
B) Date-only — قيمة Y-m-d تقويمية → بلا تحويل منطقة زمنية.
C) Country Local Business Time — ساعة جدارية للدولة (slots/hours) → ليست Absolute Moment.

قرار Owner (Step 1 Closure): **عمود واحد = دلالة زمنية واحدة**.
لا يجوز أن يحتوي العمود نفسه على خليط من UTC (مسار إدمن) وAsia/Kuwait أو +03:00
(مسار عميل/Storefront) وServer Local Time في مسارات كتابة مختلفة.


--------------------------------------------------------------------
ثالثاً: Current Country Context
--------------------------------------------------------------------
- مصدر العرض الافتراضي للإدمن: `orange_admin_context_timezone($pdo)` /
  `orange_admin_time_timezone_for_admin_context($pdo)`.
- المصدر الوحيد للـ IANA: عمود `countries.timezone` (Country Configuration).
- لا خريطة code→timezone ثابتة في التطبيق كمرجع تشغيل.
- إن غاب/بطل IANA: خطأ إعدادات واضح (`OrangeAdminTimeConfigException`) — بلا اختراع
  Asia/Kuwait صامت، وبلا Browser TZ.

--------------------------------------------------------------------
خامساً-ج: Phase 2 / Step 1 Closure (2026-07-25) — إغلاق Blockers
--------------------------------------------------------------------
قرار Owner: توحيد كتابة اللحظة في Shared Backend Writers (بما فيها مسار Storefront
الداخلي و`payment_core` و`order_intake_queue`) **فقط** لأسطر الـTimestamps — بلا ترحيل
Customer UI ولا تغيير Business Logic للطلب/الدفع/المخزون/الولاء/GL.

### DATETIME (UTC wall صريح)
- الدلالة: `Y-m-d H:i:s` = UTC wall؛ القراءة عبر `orange_admin_time_parse_mysql_utc_datetime`.
- Writers الموحّدة لـ `orders.created_at`:
  - Admin: `admin/api/orders/create-manual.php` → `orange_admin_time_utc_now_mysql()`
  - Storefront backend: `includes/order_intake_queue.php` → نفس الدالة (لا `NOW()`)
- `orders.updated_at` / `completed_at`: كتابات الإدمن + invoice_edit_helpers → UTC صريح.
- `orders.document_date`: Date-only من اليوم المحلي لـ IANA دولة الطلب — بلا تحويل بعد التحديد.

### TIMESTAMP كـ Absolute Instant (بدون Schema / بدون تغيير session TZ)
- الكتابة الآمنة: `FROM_UNIXTIME(?)` مع Unix epoch (`orange_admin_time_unix_now`) —
  لا تُرسل سلسلة UTC wall مباشرة إلى TIMESTAMP تحت session `+03:00`.
- القراءة: `UNIX_TIMESTAMP(col)` → epoch → UTC ISO (`orange_admin_time_utc_iso_from_unix`)
  ثم عرض عبر IANA دولة السجل. لا تُعامَل قيمة الجلسة الجدارية كأنها UTC.
- أُغلق:
  - `orders.paid_at` — `includes/payments/payment_core.php`
  - `payment_transactions.created_at` — نفس الملف (INSERT صريح)
  - `order_intake_queue.created_at` / `updated_at` — enqueue + process + retry APIs

### دولة السجل (مرجع العرض النهائي)
- تفاصيل طلب/دفعة: `country_id` للطلب — Fail Closed عند الغياب (`[admin_time_country_id_required]`).
- قائمة مفلترة بالدولة: يجوز Current Country Context بعد عزل الدولة.
- حركة الدفع تأخذ `country_id` من الطلب المرتبط (لا سياق الإدمن بدل السجل).

### ما أُغلق في Step 1
1. توحيد دلالة `orders.created_at` (Admin + Storefront writer)
2. `orders.updated_at` / `completed_at` بدون Default/Server local
3. `document_date` Date-only لدولة الطلب
4. `orders.paid_at` Absolute Instant
5. `payment_transactions.created_at` Absolute Instant + UTC ISO في Admin API
6. `order_intake_queue` created/updated Absolute Instant + عرض إدمن
7. Payment Review / فاتورة الإدمن / قائمة الطلبات — عرض حسب IANA الدولة
8. فلاتر اليوم: `start_utc <= ts < next_day_start_utc`
9. لا تغيير: Customer UI، Business Logic، PHP/MySQL global TZ، Schema، Backup/Restore

لم يُغيَّر: `date_default_timezone_set`، `SET time_zone` في `db()`، Schema revision، Data migration.


--------------------------------------------------------------------
خامساً-د: Phase 2 / Step 2 (2026-07-25) — المشتريات والمرتجعات
--------------------------------------------------------------------
النطاق: Admin Purchases + Purchase Returns + Sales Returns (Timestamp handling فقط).

### Absolute Moments المرحّلة
- `purchases.created_at` DATETIME → UTC wall صريح عند الإنشاء
- `purchases.updated_at` DATETIME → UTC wall صريح عند التعديل (لا NOW())
- `purchase_returns.created_at` TIMESTAMP → FROM_UNIXTIME(epoch)
- `sales_returns.created_at` TIMESTAMP → FROM_UNIXTIME(epoch)

### Date-only
- `purchases.document_date` / `purchase_returns.document_date` /
  `sales_returns.document_date` → اليوم المحلي لـ IANA دولة المستند؛ بلا تحويل بعد التخزين.

### دولة السجل
- Purchase: `purchases.country_id`
- Purchase Return: من Purchase الأصلية (`orange_purchase_return_authority_country_id`) —
  لا تُستبدل بدولة المورد عند وجود شراء مرجعي
- Sales Return: `country_id` المباشر أو من Order الأصلي
  (`orange_sales_return_authority_country_id`)
- Fail Closed عند غياب دولة السجل للعرض/التاريخ الافتراضي

### فلاتر التاريخ (داخل النطاق)
- يوم الدولة → حدود UTC: `start <= ts < next_day_start` (DATETIME)
- TIMESTAMP: عبر `UNIX_TIMESTAMP(col)` مع حدود epoch لنفس النطاق
- DST-safe لـ Africa/Cairo

### Shared writers الموحّدة (وقت فقط)
- `admin/api/purchases/create.php` / `update.php`
- `admin/api/purchase_returns/create.php` (+ authority في update للعرض/GL country)
- `admin/api/sales_returns/create.php`
- browse/get APIs + صفحات الإدمن الثلاث (عرض سيرفري؛ لا new Date على نص مبهم)

### مؤجّل Step 4 (محاسبة/قيود)
- أوقات `journal_vouchers` / `journal_lines` / `party_subledger` / pending GL queue
- `$postingAt = document_date + date('H:i:s')` (أو `+ 17:00:00`) لمسارات **الترحيل GL** — لم يُرحَّل
- ملاحظة Step 3: نفس قيمة `$postingAt` كانت تُمرَّر لـ `layer_date`/`consumed_at`؛
  التحويل إلى UTC يتم **داخل** `orange_inventory_cost_layer_add` /
  `orange_inventory_cost_layers_consume_fifo` دون تعديل متغيّر GL.

مجمّد: Backup Center / Restore Center. Step 1 و Step 2 لم يُعاد فتحهما.

### أنواع العروض المكتشفة فعلياً
1. `cart_promotions` — خصم مجموع السلة
2. `cart_gift_promotions` — هدية مجموع السلة

### Country authority
- جداول السلة/التوصيل/الرسائل: `country_id` المباشر على صف العرض
  (عند التعديل: دولة السجل؛ عند الإنشاء: سياق الدولة الحالية المفلتر).
- `offers`: `products.country_id` — Fail Closed إن غابت (لا Fallback لسياق الأدمن).
- ممنوع Asia/Kuwait / Browser / Current Context كبديل صامت عند قراءة/تقييم سجل موجود.

### Permanent offer semantics (`is_always_on`)
- العلم `is_always_on = 1` هو السلطة — لا تاريخ انتهاء وهمي (لا 2099).
- جداول NOT NULL لـ valid_*: filler تقني = يوم الدولة المحلي الحالي → UTC؛
  التقييم يتجاهل التواريخ عند always_on.
- `storefront_promo_messages`: always_on → `valid_from`/`valid_to` = NULL
  (معمارية nullable محفوظة).
- Admin/API representation (Closure): للقوائم ونموذج التعديل تُفرَّغ
  `valid_from`/`valid_to` الظاهرة عند always_on (الـfiller يبقى داخلياً فقط
  في `valid_from_utc`/`valid_to_utc` إن لزم). القائمة تعرض «تفعيل دائم».
- `updated_at` TIMESTAMP: غير ظاهر في شاشات/APIs العروض Step 4 (Internal-only).

### Scheduled offer semantics (Date-only admin contract)
- واجهة الأدمن: تاريخ فقط (Y-m-d / DMY) عبر partials الحالية — بلا ساعة.
- DATETIME storage (سلة/منتج/رسائل):
  Local calendar day (IANA دولة العرض) → UTC Absolute Moment
  (بداية اليوم 00:00 محلي → UTC؛ نهاية اليوم آخر ثانية شاملة → UTC).
- DATE storage (`delivery_fee_promotions`): يبقى Y-m-d بلا تحويل منطقة؛
  التقييم يقارن «اليوم المحلي للدولة» شاملاً.
- Inclusive محفوظ: `now >= from AND now <= to` (PHP/SQL).
- رفض: نهاية قبل البداية؛ تاريخ غير صالح؛ دولة/IANA غير صالح.

### Lifecycle timestamps (Absolute Moment UTC)
- `auto_paused_at` → `orange_admin_time_utc_now_mysql()`
- `promo_always_on_history.started_at` / `ended_at` → UTC mysql
- `promo_pause_log.paused_at` / `promo_stock_check.checked_at` → UTC mysql
- `updated_at` TIMESTAMP ON UPDATE على جداول السلة: نوع TIMESTAMP يخزّن
  Absolute Instant (تحويل جلسة MySQL→UTC داخلياً) — لم يُغيَّر Schema؛
  لا Data Migration للصفوف القديمة (كتابات DATETIME للجدولة الجديدة = UTC wall).

### Active / Upcoming / Expired
- Server-side فقط عبر UTC instant أو Country-local DATE today.
- SQL: `UTC_TIMESTAMP()` بدل `NOW()` لأعمدة DATETIME المخزّنة UTC.
- لا Browser `Date.now()` كسلطة.
- `is_active` / مخزون / أهلية تبقى كما هي (خارج تغيير الوقت).

### DST
- حدود اليوم عبر IANA (`orange_admin_time_day_bounds_*`).
- Local wall HH:MM (مساعد مشترك): nonexistent/ambiguous يفشل
  (`admin_time_local_wall_nonexistent` / `_ambiguous`) — لا اختيار صامت.
- عروض الأدمن Date-only فلا تمرّ بفجوات الساعة؛ حدود اليوم DST-safe.

### Shared evaluators المعدّل وقتها فقط
- `includes/cart_promo_schedule.php`
- `includes/storefront_promo_messages.php` (مقارنة UTC)
- `includes/delivery_areas.php` (today للدولة)
- `includes/cart_promo_monitor.php` (نافذة UTC + lifecycle UTC)
