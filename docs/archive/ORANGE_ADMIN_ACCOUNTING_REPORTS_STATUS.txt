0) سياسة GL الحالية — مغلقة (GAP-ACC-14 — للوكلاء: لا تسأل المالك عن الطابور)
================================================================================

ARABIC
- **حفظ = ترحيل GL فوري → التقارير فوراً** (ميزان، P&L، كشف حساب، ذمم).
- **إقفال التعديلات (`edit_lock`):** **رقابة فقط** — منع تعديل/حذف بعد قفل المسؤول — **لا يؤخّر** التقارير و**ليس** شرط ظهورها.
- **`gl_posting`:** redirect → **`edit_lock`** — **ليس** «انتظر ترحيل للتقارير».
- **طابور GL (`orange_gl_pending_movements`):** **legacy opt-in فقط** — `ORANGE_GL_USE_PENDING_QUEUE` في `.env.php` (**افتراضي off** على السيرفر).
- **Lane B (افتراضي):** مشتريات، سندات، YEC §9، §13 «إنشاء القيود»، INV-C — **خارج** gl_posting.
- **Lane C:** `completed` مخزون بلا GL؛ GL لاحقاً من Lane B.
- مرجع canonical: **`docs/archive/ORANGE_EDIT_LOCK_POLICY.txt`**

ENGLISH
- Save → immediate posted vouchers in reports; edit_lock = edit control only; GL pending queue legacy opt-in.

PURPOSE
- مرجع واحد لحالة **قائمة «الحسابات والتقارير»** في الأدمن + مسار GL + التقارير المرتبطة.
- للوكلاء والمالك عند «كمّل المحاسبة» أو «أغلق الثغرات» — **قبل** توسيع نطاق جديد.
- **لا يغني** عن: ORANGE_GL_MOVEMENTS_AND_POSTING_POLICY.txt، ORANGE_ACCOUNTING_MAPPING_AND_REPORT_HANDOFF.txt، docs/ACCOUNTING_REPORTING_POLICY_V2.md، ORANGE_PROJECT_COMPLETION_ROADMAP.txt (مراحل 3–6).

**§13.13 — O-01 (حالة قبل التوزيع) — مغلق 2026-05-20 (قرار مالك):**
- **لا** حالة جديدة «جاهز للتوزيع» — **`approved` (موافقة على الطلب) = جاهز للتوزيع** على المندوب.
- **التشغيل:** قبول/موافقة → **تسليم المندوب** (`delivery_agent_id`) → «بالطريق» → `completed`.
- **`pending`:** قبل الموافقة — **لا يُوزَّع** تشغيلياً (الموافقة تسبق التوزيع).
- **تنفيذ:** **لا حالة إضافية** في DB؛ §13.12: `pending` → `approved` → `on_the_way` → `completed`.

**§13.13 — O-02 (حفظ التوزيع لا يغيّر الحالة) — مغلق 2026-05-20 (قرار مالك + تنفيذ):**
- **حفظ التوزيع** يكتب **`delivery_agent_id` فقط** — **لا** `on_the_way` ولا `completed`.
- **«بالطريق»** من **`orders.php`** (فردي أو «بالطريق للكل»).
- **تنفيذ:** `handover-to-agent.php`؛ `delivery_agent_handover.php`.

**§13.13 — O-03 (متى يُربَط المندوب) — مغلق 2026-05-20 (قرار مالك + تنفيذ):**
- **`delivery_agent_id`** يُسجَّل عند **حفظ التوزيع** في **تسليم المندوب** — **ليس** عند قبول الطلب وحده.
- **طلبات الشركة** (`order_source=company`) **خارج** مسار handover API.
- **تنفيذ:** `handover-to-agent.php` + عمود المندوب في `orders.php`.

**§13.13 — O-04 (تغيير المندوب) — مغلق 2026-05-20 (قرار مالك):**
- **مسموح** تعيين/تغيير `delivery_agent_id` على **`approved`** أو **`on_the_way`** (بعد «بالطريق للكل») — **لا** `pending`.
- **ممنوع** بعد `completed` / `cancelled` / `rejected`.
- **تنفيذ:** `orange_delivery_agent_reassignable_order_statuses()` في `includes/delivery_agents.php`؛ `handover-to-agent.php`؛ `delivery_agent_handover.php` (يعرض «بالطريق» للإعادة توزيع).

**§13.13 — O-05 (ترتيب الطباعة manifest ↔ فواتير) — مغلق 2026-05-20 (قرار مالك):**
- **الترتيب الموصى به:** **ورقة المندوب (manifest)** ثم **فواتير الدفعة** (نسخة عميل + إيصال لكل طلب).
- **بدون إجبار** — زران منفصلان؛ لا قفل نظام على الترتيب.
- **تنفيذ:** `delivery_agent_handover.php` — `handoverPrintManifest()` ثم `handoverPrintInvoices()`.

**§13.13 — O-06 (متى تُطبَع + إعادة الطباعة) — مغلق 2026-05-20 (قرار مالك + تنفيذ):**
- **سير العمل:** توزيع → **حفظ التوزيع** → **طباعة** (ورقة ثم فواتير — O-05).
- **بعد أي تعديل توزيع:** الحفظ التالي = **دورة جديدة** — **احفظ ثم اطبع من جديد** (الورقة تعتمد `delivery_agent_id` في DB).
- **إعادة الطباعة حرة** بعد الحفظ — **لا** قفل على أزرار الطباعة.
- **تنفيذ:** `delivery_handover_manifest.php` يتحقق من `delivery_agent_id`؛ prompt طباعة بعد نجاح الحفظ في `delivery_agent_handover.php`.

**§13.13 — O-07 (إعادة طباعة دفعة) — مغلق 2026-05-20 (قرار مالك):**
