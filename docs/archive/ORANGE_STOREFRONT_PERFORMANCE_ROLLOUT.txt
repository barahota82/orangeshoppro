ORANGE — أرشيف خطة أداء الواجهة وترحيل المخطط (إلزام الوكلاء عند العمل في هذا النطاق)
================================================================================
المسار: docs/archive/ORANGE_STOREFRONT_PERFORMANCE_ROLLOUT.txt
تاريخ الأرشيف: 2026-04-26

الغرض
-------
وثيقة تشغيلية تربط **تحسين أداء الواجهة** و**مسار ترحيل قاعدة البيانات** بـ:
- سياسة المالك في الواجهة والقنوات والطلب (المرجع أدناه)،
- مرجع التشغيل IBRAHIM،
- تقليل المخاطر والتراجع.

**إلزام القراءة:** أي وكيل يعمل على **أداء المتجر العام**، أو **orange_catalog_ensure_schema**، أو **مسار الواجهة + قاعدة البيانات** معاً — يجب أن يطلع على **هذا الملف فعلياً** إضافة إلى الملفات الإلزامية الأخرى في `.cursor/rules/orange-session-handoff.mdc`.


--------------------------------------------------------------------
أولاً: القراءات الإلزامية (قبل أي تنفيذ في هذا النطاق)
--------------------------------------------------------------------
1. **docs/archive/ORANGE_STOREFRONT_POLICY_REFERENCE.txt** — سياسة الواجهة والقنوات (س25/س26، كود الدولة، السلة، التتبع، …).
2. **IBRAHIM_ORANGE_MASTER.txt** — خاصة §2 (ensure_schema، migrations)، §4 (ترتيب SQL)، و§10 إن وُجد (ربط القنوات).
3. **.cursor/rules/orange-session-handoff.mdc** و **orange-continuity.mdc** و **orange-php-utf8-workflow.mdc**.
4. **هذا الملف** — ORANGE_STOREFRONT_PERFORMANCE_ROLLOUT.txt.
5. **`scripts/orange_db.sql`** — عند العمل على مخطط/جداول/ترحيل: لقطة «الحقيقة» (IBRAHIM §2أ)؛ راجع الأجزاء المعنية فقط؛ قد لا يُرفع في Git.


--------------------------------------------------------------------
ثانياً: ما يجب ألا يُكسر (سياسة العمل)
--------------------------------------------------------------------
- **س25/س26:** رابط قناة → نفس القناة؛ URL يحدد القناة → كما هو؛ نطاق فقط → آخر قناة زارها (كوكي/منطق مسار).
- **لا تُغيّر** منطق **current_channel_slug()**، **storefront-dispatch.php**، أو كوكي القناة/اللغة **ذريعة الأداء** دون موافقة المالك ومراجعة المرجع المؤرشف.
- **نماذج الهاتف (قسم «صفر»):** قائمة كود دولة + رقم محلي/خيار دولي — لا تُبسَّط على حساب السياسة.
- **السلة والطلب والتتبع:** لا «وضع متدهور» يخفي أعطال ترحيل عن العميل على مسارات إلزامية دون سياسة مكتوبة من المالك.


--------------------------------------------------------------------
ثالثاً: الوضع التقني المرجعي في المستودع (ملخص)
--------------------------------------------------------------------
- **orange_catalog_ensure_schema()** في includes/catalog_schema.php: ترحيل PHP + فحوص؛ موثّق في IBRAHIM كمسار تشغيل لقواعد قد تحتاج تحديثاً تلقائياً.
- **scripts/migrations/*.sql** مع جدول **orange_schema_migrations**: ترحيلات ملفية.
- **orange_catalog_schema_checkpoint** و **ORANGE_CATALOG_SCHEMA_PHP_REVISION**: مسار سريع عند تطابق الإصدار مع القاعدة؛ يُرفع الرقم عند إضافة خطوات ترحيل PHP جديدة في ensure_schema (راجع تعليق الملف).
- **orange_schema_meta** (جدول version + updated_at) و **ORANGE_SCHEMA_CODE_VERSION** (مرادف لرقم المراجعة أعلاه): بوابة إصدار موازية؛ المسار السريع إذا تطابق **أي** من checkpoint أو meta مع رقم الكود؛ يُزامَن الصف الناقص تلقائياً عند أول طلب سريع.
- **orange_schema_check_and_bootstrap($pdo)**: غلاف يستدعي **orange_catalog_ensure_schema** — للتوافق مع تسميات خطط النشر؛ لا يحذف جسم الترحيل PHP.
- **scripts/run_migrations.php**: تشغيل CLI لـ **orange_run_migrations** (غلاف النشر؛ نفس **orange_catalog_ensure_schema**) بعد **git pull** (اختياري لتخفيف أول زيارة واجهة).
- **index.php** و **manifest.php** و **storefront-dispatch.php**: تخفيف جزئي على مسارات معيّنة؛ الترحيل الكامل لصفحات الواجهة يمر عبر استدعاءات الصفحات/الهيدر حسب التصميم الحالي للمشروع.

**ملاحظة:** استبدال **كامل** جسم ensure_schema بملفات SQL مرقمة فقط (001..N) **لم يُنفَّذ** — يتطلب هجرة منفصلة وموافقة مالك؛ الخطوات أعلاه تضيف **بوابة إصدار + CLI** دون إسقاط IBRAHIM.


--------------------------------------------------------------------
رابعاً: تقليل المخاطر قبل أي تغيير إضافي
--------------------------------------------------------------------
1. **نسخة احتياطية كاملة** لقاعدة البيانات (مطابق لروح IBRAHIM قبل تنفيذ SQL).
2. تسجيل **نقطة Git** قبل التعديل:
   - `git rev-parse HEAD` أو وسم: `git tag -a قبل-التعديل-YYYYMMDD ...`
3. بيئة **staging** عند الإمكان بنفس إصدار PHP/MySQL تقريباً.
4. **عدم** إزالة **orange_catalog_ensure_schema** من كل مسارات الواجهة دفعة واحدة دون: بديل نشر/CLI/أدمن موثّق وموافقة المالك (يخالف نموذج IBRAHIM الحالي إن بقي الترحيل معتمداً على «أول طلب»).


--------------------------------------------------------------------
خامساً: التراجع (للمالك أو للوكيل بتوجيه المالك)
--------------------------------------------------------------------
- استرجاع الكود: `git reset --hard <الهاش_المحفوظ>` (مع الحذر من push --force على فرع مشترك).
- استرجاع القاعدة: استيراد dump الاحتياطي الذي أخذه المالك (لا يحدث تلقائياً مع Git).


--------------------------------------------------------------------
سادساً: جملة توجيه للمالك عند الرغبة بالتراجع
--------------------------------------------------------------------
يمكن للمالك كتابة للوكيل:
«أرجع المستودع إلى الالتزام [الهاش] قبل إصلاحات الأداء، مع عدم المساس بسياسة القنوات.»


--------------------------------------------------------------------
سابعاً: ملاحظة عن «صفر مخاطر»
--------------------------------------------------------------------
لا يوجد صفر مطلق في النشر؛ الهدف هو **بوابات + نسخ احتياطي + مراحل + تراجع واضح**.


--------------------------------------------------------------------
ثامناً: مقابلة فكرة «Schema Gate + Versioned Migrations + Safe Fallback»
--------------------------------------------------------------------
مرجع للمقارنة مع مقترحات «معماريّة نهائية» (بوابة إصدار، ترحيل ملفي، وضع متدهور، كاش):

- **إصدار مخطط في القاعدة (`orange_schema_meta` + رقم في الكود):** منفّذ؛ **ORANGE_SCHEMA_CODE_VERSION** مرادف لـ **ORANGE_CATALOG_SCHEMA_PHP_REVISION** (رقم واحد مصدر الحقيقة).
- **مسار سريع بعد التطابق:** إن تطابق **checkpoint** أو **meta** مع رقم المراجعة → يُشغَّل **فقط** `orange_schema_run_pending_migrations` (ملفات SQL المسجّلة) ثم إنهاء؛ دون إعادة جسم PHP الكامل.
- **غلاف `orange_schema_check_and_bootstrap`:** منفّذ؛ يستدعي **نفس** `orange_catalog_ensure_schema` (مبدأ IBRAHIM: الترحيل التلقائي ما زال موجوداً؛ تغيّر **أسلوب التنفيذ** عبر البوابة والـ CLI لا يلغي المبدأ).
- **ترحيل حصري بملفات `001.sql`…`NNN.sql` وحلقة صارمة تحل محل جسم PHP:** غير منفّذ في هذا المستودع — الترحيل الفعلي ما زال **PHP + `scripts/migrations/*` + جدول `orange_schema_migrations`**؛ استبدال كامل يحتاج مشروع هجرة وموافقة مالك.
- **وضع متدهور على الواجهة العامة (`ORANGE_SCHEMA_DEGRADED` + إخفاء ميزات):** غير معتمد هنا — مسارات السلة والطلب والتتبع لا يجب أن تخفي فشل ترحيل دون سياسة مكتوبة (راجع «ثانياً» أعلاه).
- **كاش APCu / Redis / ملف tmp لتخطي فحص الإصدار:** غير مضاف — مخاطرة بيانات قديمة أو بيئات بلا APCu.
- **س25/س26 والقنوات:** لم تُغيّر ذريعة هذا المسار.
- **نشر مسبق:** `php scripts/run_migrations.php` (CLI) يكمّل «أول زيارة» عند تشغيله صراحةً على السيرفر.
