ORANGE — خطة «معاينة المنتج قبل النشر» (جلسة تصفّح كاملة للموقع كعميل)
================================================================================
المسار: docs/archive/ORANGE_PRODUCT_PREPUBLISH_PREVIEW_ROLLOUT.txt
تاريخ الأرشفة: 2026-06-23
الحالة: **خطة معتمَدة الاتجاه — لم تُنفَّذ بعد** (نقاش مالك؛ التنفيذ مؤجّل لجلسة لاحقة).
آخر تنقيح: 2026-06-23 — **النموذج المعتمد صار «جلسة معاينة على مستوى الموقع (شبيهة بالقناة، مقيّدة بجلسة أدمن) + صفّ ظِلّ/مسودّة»** بدل «معاينة صفحة واحدة بتوكن». السبب: المالك يريد **تصفّح الموقع كاملاً كعميل** (سلة + تتبّع طلب حقيقي) لا صفحة منتج واحدة. القسم «صفر-أ» يوضّح تطوّر القرار.

--------------------------------------------------------------------
صفر-أ: تطوّر القرار (سجل النقاش)
--------------------------------------------------------------------
1. الطرح الأول: معاينة صفحة منتج واحدة عبر «صفّ مسودّة + توكن» (`full_draft`).
2. اقتراح المالك: «اعمل حاجة شبيهة بالقنوات تعرض المحفوظ وغير المحفوظ، لا تظهر للعميل، خاصة بصفحة الأدمن.»
3. تحليل: آلية القنوات ممتازة لطبقة **الرؤية/السياق** (تُلازم الزائر أثناء التنقّل وتُعيد استخدام قالب المتجر الحقيقي)، لكنها **لا** تحمل البيانات غير المحفوظة — تلك يجب أن تُخزَّن سيرفرياً (صفّ ظِلّ/مسودّة) لأن `pages/product.php` يقرأ من القاعدة.
4. توضيح المالك للنطاق: «أتصفّح الموقع كاملاً كعميل، أقدر أعمل أوردر بالسلة لكن لا يُرسَل فعلياً للأدمن، وأتتبّع أوردر حقيقياً موجوداً؛ إرسال داتا فعلية للأدمن كطلب عميل غير مسموح.»
5. النتيجة: المسار «POST بلا حفظ لصفحة واحدة» **يُرفض** لأنه ينكسر عند التنقّل. المعتمد: **جلسة معاينة على مستوى الموقع** (فكرة المالك مرفوعةً) **+ صفّ ظِلّ/مسودّة** للمنتج قيد التعديل.

**قرارات المالك المثبّتة (2026-06-23):**
- **نطاق الرؤية:** **فقط المنتج/المنتجات قيد المعاينة** تُجبَر على الظهور؛ باقي الموقع كما يراه العميل (لا كشف لكل المسودّات/الموقوفات).
- **الطلب في المعاينة:** عند «إرسال الطلب» تظهر **رسالة نجاح وهمية «هذا طلب معاينة — لم يُرسَل»** (تجربة أقرب للحقيقية) — **بلا** إنشاء طلب، **بلا** حجز مخزون، **بلا** بيانات للأدمن، **بلا** واتساب.
- **رصيد متغيّر جديد لم يُحفظ:** يُعرض **بالكمية المُدخلة** في النموذج كما هي.

أولاً: الهدف (كما حدّده المالك)
--------------------------------------------------------------------
زر في شاشة المنتج بالأدمن يفتح **جلسة معاينة كاملة** يتصفّح فيها المالك **الموقع الحقيقي كعميل**، مع ظهور المنتج قيد التعديل **بحالته المحفوظة + غير المحفوظة**، ليراجع: الدليل الإرشادي، السعر، الصور، الألوان، المقاسات، وتجربة السلة/الطلب — كل ذلك دون أي أثر فعلي (لا طلب حقيقي، لا مخزون، لا بيانات أدمن). المعاينة **مخفيّة عن العميل** و**مقيّدة بجلسة أدمن**. المرجع البصري هو **قالب المتجر الحقيقي** (`pages/product.php` + `includes/header.php` + CSS/JS الواجهة)، لا محاكاة الأدمن.

--------------------------------------------------------------------
ثانياً: المعمارية المعتمدة (طبقتان)
--------------------------------------------------------------------
**الطبقة 1 — جلسة المعاينة (سياق شبيه بالقناة، مقيّدة بأدمن):**
- تُنشأ من شاشة المنتج بالأدمن (بعد تحقق جلسة الأدمن وصلاحيته) → السيرفر يضبط **كوكي/توكن جلسة معاينة موقّعاً** (مثلاً `orange_preview_session`) يحمل: `preview_admin_id`، مجموعة معرّفات المنتجات المُعايَنة (staged ids)، `country_id` للمعاينة، و`expires_at`.
- الواجهة تتعرّف على الجلسة في مسار السياق (نفس نقطة منطق القناة في `config.php`/`includes/header.php`) **فقط** عند وجود الكوكي وصلاحيته → تدخل «وضع المعاينة» الذي يُلازم الزائر أثناء التنقّل (تماماً كما يُلازمه سياق القناة).
- **مقيّدة بأدمن:** لأن القنوات تُفتح بالرابط للعامة (س25/س26)، جلسة المعاينة **ليست قناة عامة** — لا تُنشأ إلا من الأدمن، ولا يدخلها عميل.

**الطبقة 2 — صفّ ظِلّ/مسودّة (يحمل المحفوظ + غير المحفوظ):**
- صفّ في `products` بعلم `is_preview_draft = 1` يُكتب من بيانات نموذج المنتج (المحفوظة وغير المحفوظة) قبل فتح المعاينة، مع صوره ومتغيّراته.
- **منتج قائم:** صفّ ظِلّ مستقل (`preview_source_product_id = <id الأصلي>`) — **لا تُلمَس النسخة الحيّة**.
- **منتج جديد:** صفّ مسودّة واحد لكل أدمن (يُعاد استخدامه عند التحديث، لا تكديس).
- جلسة المعاينة تشير إلى **id صفّ الظِلّ/المسودّة**، فيظهر هذا الصفّ في صفحات الموقع داخل وضع المعاينة بدلاً من/إضافةً إلى الأصلي حسب الحاجة.

--------------------------------------------------------------------
ثالثاً: سلوك «وضع المعاينة» على الموقع (مطابقة طلب المالك)
--------------------------------------------------------------------
| المطلوب | السلوك في وضع المعاينة |
|---|---|
| تصفّح الموقع كاملاً كعميل | قالب المتجر الحقيقي؛ جلسة المعاينة تُلازم التنقّل |
| ظهور المنتج المُعايَن (محفوظ + غير محفوظ) | يُجلب صفّ الظِلّ/المسودّة لمعرّفاته؛ يُتجاوز `is_active=1` **فقط لمعرّفات الجلسة** (نطاق «فقط المُعايَن») |
| باقي الموقع | كما يراه العميل تماماً (لا كشف لمسودّات/موقوفات أخرى) |
| بناء طلب في السلة | السلة عميلة (localStorage) تعمل؛ معاينة العربة `api/cart/checkout-preview.php` (قراءة فقط) تعمل وتُظهر الإجماليات/العروض حقيقية |
| إرسال الطلب | **محجوب**: `api/orders/create-order.php` و`api/orders/amend-order-items.php` والطابور تكتشف جلسة المعاينة → **لا تُنشئ/تحجز/تُسجّل** → تُرجِع **نجاحاً وهمياً «طلب معاينة — لم يُرسَل»** |
| تتبّع طلب حقيقي موجود | `api/orders/get-order.php` (قراءة فقط) **مسموح** |
| رصيد متغيّر جديد لم يُحفظ | يُعرض بالكمية المُدخلة في النموذج |
| الفهرسة/التسريب | `noindex` + **شارة «وضع معاينة» ثابتة** في كل صفحات الموقع |

رابعاً: نموذج البيانات (في `includes/catalog_schema.php` فقط، idempotent + رفع الإصدار)
--------------------------------------------------------------------
أعمدة على `products` (منفّذة في `catalog_schema.php` rev 100، idempotent):
- `is_preview_draft`  TINYINT(1) NOT NULL DEFAULT 0  + فهرس `idx_products_is_preview_draft`
- `preview_admin_id`  INT NULL           (الأدمن صاحب الصفّ)
- `preview_token`     VARCHAR(64) NULL    + فهرس `idx_products_preview_token` (توكن عشوائي للتحقّق — يُنشأ من API الأدمن فقط)
- `preview_source_product_id` INT NULL   (المنتج الأصلي عند الظِلّ؛ NULL للجديد) + فهرس `idx_products_preview_owner(preview_admin_id, preview_source_product_id)`
- `preview_expires_at` DATETIME NULL      (تنظيف)

ملاحظات:
- `country_id` **إلزامي** على صفّ الظِلّ = دولة المعاينة (§13).
- صور الظِلّ في `product_images` بمعرّف الصفّ؛ متغيّراته في `product_variants` عبر `includes/product_variants_write.php`.
- **التحقّق:** كوكي المعاينة يحمل `<draftId>:<preview_token>`؛ يُتحقَّق بمطابقة صفّ ظِلّ نشِط غير منتهٍ بنفس التوكن — لا حاجة لسرّ توقيع ولا جدول جلسات منفصل.

--------------------------------------------------------------------
خامساً: إخفاء صفوف الظِلّ عن العميل (أخفّ من الخطة الأولى)
--------------------------------------------------------------------
بما أن نطاق الرؤية «فقط المُعايَن»، **لا** نحتاج تجاوز `is_active` على مستوى الموقع؛ التجاوز محصور بمعرّفات الجلسة على صفحة المنتج. لكن يبقى **إلزامياً** ألّا يتسرّب صفّ ظِلّ (خصوصاً منتج جديد) إلى قوائم/بحث/خريطة العميل:
- أضِف `AND is_preview_draft = 0` إلى استعلامات القوائم/البحث/المشابهات/الخريطة التي تقرأ من `products` (تدقيق موجّه — أخفّ بكثير من تجاوز شامل).
- صفحة المنتج المباشرة (`pages/product.php` سطر 20) تبقى للعميل بـ `is_active=1`؛ وضع المعاينة فرع منفصل لمعرّفات الجلسة فقط.
**معيار إنجاز:** صفّ ظِلّ لا يظهر لأي زائر بلا جلسة معاينة صالحة، في أي مسار واجهة.

سادساً: نقاط الكود المتأثّرة (مرجع تنفيذ)
--------------------------------------------------------------------
- **المخطط:** `includes/catalog_schema.php` (أعمدة المعاينة + فهارس + رفع `ORANGE_CATALOG_SCHEMA_PHP_REVISION`).
- **جلسة المعاينة:** ضبط/قراءة الكوكي الموقّع — نقطة سياق الواجهة (`config.php`/`includes/header.php`) **دون كسر** `current_channel_slug()` ولا كوكي القناة `orange_sf_ch`.
- **مساعد كتابة مشترك:** استخراج منطق إدراج/تحديث المنتج وصوره ومتغيّراته من `admin/api/products/create.php` و`update.php` إلى `includes/product_write.php` (يستدعيه الثلاثة + API الظِلّ) لضمان تطابق سلوك الحفظ. (الصور تُرفع مسبقاً عبر `admin/api/uploads/product-image.php` كأسماء ملفات في `/uploads/products/`؛ صفّ `product_images` يُدرَج عند الحفظ — `create.php` سطر 393.)
- **API الظِلّ:** `admin/api/products/save-preview-draft.php` (جديد/ظِلّ + صور + متغيّرات + دولة) → يُنشئ جلسة المعاينة ويعيد رابط بدء التصفّح.
- **صفحة المنتج:** `pages/product.php` (سطر 20 + حارس الدولة 23–30 + حارس السلسلة الموحّدة 31–37) — فرع معاينة لمعرّفات الجلسة فقط؛ ضبط سياق الدولة على دولة الجلسة فيمرّ حارس الدولة؛ تجاوز حارس السلسلة في المعاينة مع تنبيه أن النشر الحقيقي يتطلّب سلسلة نشطة.
- **حجب الطلب:** `api/orders/create-order.php` و`api/orders/amend-order-items.php` و`includes/order_intake_queue.php` — حارس «إن كانت جلسة معاينة» → نجاح وهمي بلا أثر.
- **مسموح قراءة فقط:** `api/cart/checkout-preview.php` و`api/orders/get-order.php`.
- **واجهة الأدمن:** `admin/pages/products.php` — زر «معاينة كاملة (تصفّح كعميل)» + منتقي دولة المعاينة + «تحديث المعاينة»؛ يفتح الموقع في `iframe` غامر أو تبويب جديد؛ تبقى المحاكاة السريعة الحالية كخيار ثانوي.

- **الأمان:** الكوكي موقّع وقصير العمر؛ الجلسة لا تُنشأ إلا بجلسة أدمن صالحة؛ صفوف الظِلّ مخفيّة في كل مسارات العميل؛ `noindex` + شارة معاينة؛ الطلب محجوب؛ `ORANGE_API_DEBUG` مطفأ على الإنتاج.

- **النشر/الترميز:** المخطط في `catalog_schema.php` (idempotent) + رفع الإصدار ثم `git push` (لا SQL يدوي)؛ UTF-8 بلا BOM؛ `php -l` + `verify-php-utf8.ps1` قبل commit؛ تسجيل أي صفحة أدمن جديدة في `$allowed`.
- **التراجع:** نسخة احتياطية + وسم Git قبل التنفيذ.

ثامناً: ترتيب التنفيذ (مراحل + معيار إنجاز)
--------------------------------------------------------------------
- **P1 — المخطط:** أعمدة + فهارس + رفع الإصدار. معيار: idempotent بعد `git pull`.
- **P2 — إخفاء صفوف الظِلّ:** `is_preview_draft=0` على استعلامات القوائم/البحث/الخريطة (تدقيق موجّه). معيار: لا تسرّب.
- **P3 — مساعد الكتابة المشترك:** `includes/product_write.php` دون تغيير سلوك create/update. معيار: انحدار صفري.
- **P4 — API الظِلّ + جلسة المعاينة:** حفظ الظِلّ + إنشاء الكوكي الموقّع + رابط البدء. معيار: ظِلّ مطابق للنموذج + جلسة صالحة.
- **P5 — وضع المعاينة على الموقع:** فرع معرّفات الجلسة في `pages/product.php` + سياق الدولة + `noindex` + شارة + ملازمة التنقّل. معيار: تصفّح كامل بوضع معاينة للأدمن فقط.
- **P6 — حجب الطلب + السماح بالقراءة:** حراس create-order/amend/queue (نجاح وهمي) + إبقاء checkout-preview/get-order. معيار: لا طلب فعلي ولا حجز ولا بيانات أدمن؛ التتبّع يعمل.
- **P7 — واجهة الأدمن:** الزر + منتقي الدولة + التحديث + iframe. معيار: تدفّق كامل من النموذج إلى تصفّح الموقع.
- **P8 — التنظيف والأمان:** انتهاء الصلاحية + تنظيف صفوف الظِلّ + مراجعة أمنية. معيار: لا تكدّس؛ لا وصول بلا جلسة.

--------------------------------------------------------------------
تاسعاً: القرارات المفتوحة — **أُغلقت (قرار مالك 2026-06-23)**
--------------------------------------------------------------------
1. **نموذج المعاينة (قرار مالك نهائي 2026-06-23 — `keep_session`):** المعاينة **سياق خاص بالأدمن** عبر
   **كوكي + توكن عشوائي** فوق المتجر الطبيعي — **وليست قناة عامة جديدة**. سبب الرفض: حسب س25/س26 القنوات
   **قابلة للفتح علناً**، فقناة معاينة حقيقية تُسرّب المسودّة أو تستلزم استثناءً عن نموذج القنوات. الإخفاء مضمون
   عبر `is_active=0` + التوكن لا عبر عضوية القناة. المعاينة تفتح على **القناة الرئيسية للدولة** كوسيلة لضبط سياق الدولة فقط.
   **تصحيح (قرار مالك 2026-06-23):** الهوية/العرض (الشعار، الواجهة) **موحّدة وثابتة للموقع كله** عبر كل القنوات وكل الدول
   (أُلغيت فكرة شعار لكل قناة وثُبّت الشعار) — فالقنوات **لا تختلف بالعرض/الهوية**. عملياً: اختيار القناة في المعاينة
   لا يغيّر الشكل، بل يحدّد **سياق الدولة** فقط (العملة/المخزون/التوفّر لكل دولة). لذلك «منتقي القناة» داخل الشارة
   بلا قيمة بصرية وأُسقط من النطاق؛ المهم **منتقي الدولة** (منفّذ في P7).
   **ضمان الإخفاء (تأكيد للمالك):** صفّ المعاينة `is_preview_draft=1` + `is_active=0`، مُستبعَد من كل استعلامات
   العميل، ولا يتحوّل **أبداً** تلقائياً إلى منتج حيّ — إنشاء المنتج الحقيقي إجراء منفصل (`create.php`). فلا ظهور
   لأي منتج غير محفوظ للعميل قبل الحفظ الفعلي.
2. **العمر/التنظيف:** جلسة المعاينة وصفّ الظِلّ **ينتهيان خلال 24 ساعة** (`preview_expires_at = NOW() + 24h`)؛ **تنظيف lazy** للمنتهية صلاحيتها عند فتح معاينة جديدة لنفس الأدمن؛ **+ سكربت صيانة اختياري** (`scripts/maintenance_*`) لتنظيف دوري.
3. **تدقيق استعلامات القوائم/البحث (بند تقني، لا قرار مالك):** يُنفَّذ في مرحلة **P2** كمسح شامل موثّق لإضافة `is_preview_draft=0`.

--------------------------------------------------------------------
عاشراً: مرجع سريع (إنجليزي للوكلاء)
--------------------------------------------------------------------
Goal: full-site, customer-like **preview session** (not a single page) using the real storefront templates. Owner wants to browse the whole site, build a cart, and track a real existing order — but NEVER submit a real order (no order row, no stock reservation, no admin data).
Model (two layers): (1) **admin-gated preview SESSION** = channel-like context carried via a signed cookie (`preview_admin_id`, staged product ids, country, expiry); travels across navigation like the channel context; only created from admin (channels are publicly openable per s25/s26, so this is NOT a public channel). (2) **shadow/draft row** in `products` (`is_preview_draft=1`, `preview_source_product_id` for existing) holding saved+unsaved data, images, variants.
Preview-mode behavior: force-show ONLY the staged product id(s) (bypass `is_active` for those ids only); rest of site as a customer sees it; cart + `checkout-preview` work (read-only); `create-order`/`amend`/intake queue are sandboxed → **fake success "preview order — not sent"**; `get-order` tracking allowed (read-only); new unsaved variant stock shows the **entered quantity**; `noindex` + persistent preview banner.
Hide shadow rows from customers: add `is_preview_draft=0` to listing/search/sitemap queries (targeted audit; lighter than a global `is_active` bypass).
Constraints: zero cost on customer hot path (only branch when preview cookie present); per-country context (§13); schema via `catalog_schema.php` + bump revision + `git push` (IBRAHIM §2); UTF-8 no BOM.
Owner decisions (2026-06-23): visibility = only previewed product; order send = simulated success; new-variant stock = entered quantity.
Owner decisions (2026-06-23, follow-up): preview model = admin-gated cookie+token SESSION, NOT a new public channel (`keep_session`) — channels are publicly openable (s25/s26), and hiding is guaranteed by `is_active=0`+token, not channel membership. Branding/identity is UNIFIED and fixed site-wide across all channels and countries (per-channel logo idea dropped); channel choice in preview only sets COUNTRY context, not appearance — so an in-banner channel picker is out of scope. A draft NEVER auto-promotes to a live product (real save = separate `create.php`).
Resolved: preview model (session, not channel); TTL = 24h + lazy + optional maintenance script; listing-query audit done in P2.
