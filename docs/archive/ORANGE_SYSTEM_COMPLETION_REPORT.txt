2) معمارية GL — ثلاثة lanes (إلزامي للفهم)
================================================================================

Lane A — الطابور (gl_posting hub عند orange_gl_use_pending_queue()):
  - مشتريات create/update، مردودات مشتريات
  - opening_balances (OBV)
  - سندات يدوية **جديدة** (journal/manage create)
  - CRR / SPR (partner receipts)
  - orange_gl_pending_movements + pending-list/post/unpost

Lane B — ترحيل مباشر (by design — **خارج** gl_posting):
  - §9 YEC: year_end_close.php → year_end_close_vouchers (rev 63)
  - §13 «إنشاء القيود»: final-posting-create.php → order_fulfillment GL + INV-O
  - manual_order / create-manual.php → INV-C + GL
  - مراجع: ORANGE_GL_MOVEMENTS §9.8، §13.9

Lane C — بلا GL:
  - completed = مخزون فقط (قبل final posting)
  - opening_stock_balances = كميات بلا قيد (§11؛ OBV مالي منفصل)

ORANGE_GL_IMMEDIATE_POSTING=1 على السيرفر = bypass تطويري — ليس بالضرورة «ثغرة».

**GAP-ACC-02 ملغى:** GL على **حفظ** المشترية (purchases/create.php enqueue)، وليس receive منفصل.
