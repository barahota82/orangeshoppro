ORANGE — مخطط جاهزية الدفع الإلكتروني (تحويل بنكي مباشر + بوابة دفع)
================================================================================
المسار: docs/archive/ORANGE_ONLINE_PAYMENT_READINESS.txt
تاريخ: 2026-06-05
الحالة: **مخطط تنفيذ معتمد للجاهزية — لم يُنفَّذ بعد** (الدفع مؤجّل بقرار المالك §7 multicountry vision).
المصدر: نقاش مالك–وكيل (2026-06-05).

الغرض
-------
تجهيز النظام ليُفعَّل الدفع الإلكتروني عند الحاجة بنموذجين، دون إعادة هيكلة:
  (أ) **تحويل بنكي مباشر** لحساب الشركة (يدوي + تأكيد أدمن).
  (ب) **شركة دفع أونلاين** تُحصّل نيابةً (بوابة مثل MyFatoorah — KNET/بطاقات).

**إلزام القراءة:** عند أي تنفيذ يخص الدفع — اقرأ هذا الملف + `ORANGE_STOREFRONT_POLICY_REFERENCE.txt` (الطلب/التتبع) + `ORANGE_ACCOUNTING_MAPPING_AND_REPORT_HANDOFF.txt` (قيد التحصيل) + `ORANGE_OWNER_MULTICOUNTRY_VISION.txt` §7 (الدفع per دولة).

--------------------------------------------------------------------
مبدأ التصميم
--------------------------------------------------------------------
- طبقة **«دفعات» موحّدة** للطلب، تحتها **طرق دفع** (method) قابلة للتشغيل/الإيقاف **لكل دولة**.
- كل طريقة = **موصِّل (connector)**: يدوي (بنكي) أو آلي (بوابة) — بواجهة موحّدة.
- **نفس** مسار حالة الدفع والمحاسبة للجميع. الأسرار في `.env.php` على السيرفر فقط.
- **توافق:** فوق البنية الحالية (طلبات/GL/سند قبض/تعدد الدول/عملة م4) — لا يكسر المتجر/المحاسبة؛ يبقى **مُعطّلاً** حتى التفعيل per country per method.

--------------------------------------------------------------------
المرحلة 0 — الأساس الموحّد (مطلوب للنموذجين)
--------------------------------------------------------------------
**DB (ترحيل في includes/catalog_schema.php — آمن لإعادة التشغيل):**
- `orders`: `payment_status` ENUM-like (`unpaid`/`pending_review`/`paid`/`failed`/`refunded`)، `payment_method`, `paid_at`, `amount_paid` (موجود جزئياً).
- **`payment_transactions`**: `id, order_id, country_id, method, provider, amount, currency, status, provider_ref, txn_uuid UNIQUE, raw_payload TEXT, created_at` — سجل تدقيق + **idempotency**.
- **`payment_methods`**: `country_id, method (bank|gateway), provider, is_active, sort_order` — تشغيل per دولة.

**برمجياً:**
- `includes/payments/payment_core.php` — حالة الدفع + idempotency + **ربط GL** (قيد تحصيل: مدين بنك/خزينة · دائن العميل/الإيراد) يعيد استخدام منطق سند القبض الحالي؛ **مرة واحدة** لكل `txn_uuid`.
- العملة: `orange_country_functional_currency_code` (جاهزة).
- الإعدادات: توسيع `payment_online_enabled` الحالي → إعدادات دفع per دولة.

--------------------------------------------------------------------
المرحلة 1 — تحويل بنكي مباشر (يدوي)
--------------------------------------------------------------------
**التدفّق:** اختيار «تحويل بنكي» → عرض بيانات حساب الشركة (per دولة) → العميل يحوّل ويرفع إثبات + مرجع → الطلب `pending_review` → الأدمن «تأكيد الدفع» → `paid` + قيد GL تحصيل بنكي.

**يُبنى:**
- `company_bank_accounts` (per دولة: اسم البنك/IBAN/الحساب/العملة).
- خيار «تحويل بنكي» في checkout (`assets/js/cart.js` + `pages/cart.php`) + رفع إثبات `api/payments/bank-proof.php` (صورة في uploads).
- شاشة أدمن **«مراجعة الدفعات»** (`admin/pages/payment_review.php`): قائمة `pending_review` + عرض الإيصال + تأكيد/رفض + صلاحية + audit + edit_lock.
- **سياسة (قرار مالك عند التفعيل):** هل التسليم/الحجز النهائي قبل أم بعد `paid`.

--------------------------------------------------------------------
المرحلة 2 — بوابة دفع أونلاين (MyFatoorah أو مماثل)
--------------------------------------------------------------------
**التدفّق (Hosted):**
1. checkout → `api/payments/gateway-create.php` يستدعي البوابة (المبلغ + رقم الطلب) → يُرجع `PaymentURL`.
2. تحويل العميل لصفحة البوابة → يدفع (لا تلمس بيانات البطاقة).
3. عودة → `pages/payment-return.php` (Callback) **و** Webhook `api/payments/gateway-webhook.php`.
4. **تأكيد خادمي** (`GetPaymentStatus`) + **تحقق توقيع** الـ webhook → `paid` + قيد GL + idempotency (`txn_uuid`).

**يُبنى:**
- `includes/payments/gateway_myfatoorah.php` — موصِّل بواجهة موحّدة `create()/verify()/webhook()` (يسهّل إضافة مزوّد آخر).
- إعدادات (Token test/live، Mode، BaseURL، webhook secret، العملات) **في `.env.php` فقط** — لا أسرار في Git.
- `payment_return.php` + `gateway-webhook.php` (تحقق توقيع + منع ازدواج).

**أمان إلزامي:**
- أسرار في `.env.php` فقط؛ لا تثق بإعادة التوجيه (أكّد خادمياً)؛ تحقّق توقيع الـ webhook؛ منع الازدواج عبر `txn_uuid` UNIQUE.
- **لا يُخزَّن IP شركة الدفع في خانة** — الأمان بالتوقيع/السر؛ (اختياري: تقييد نطاقات IP للـ webhook كطبقة إضافية فقط، لا بديل عن التوقيع). أحياناً تطلب الشركة تسجيل IP سيرفرك **في لوحتهم** — خارج النظام.

--------------------------------------------------------------------
ما يلزم من المالك عند التفعيل (لا الآن)
--------------------------------------------------------------------
- **بنكي:** بيانات حسابات الشركة لكل دولة + سياسة التسليم قبل/بعد تأكيد الدفع.
- **بوابة:** اسم الشركة + مفاتيح test/live + العملات المدعومة لكل دولة + ربط حساب البنك/التحصيل في الدليل.
