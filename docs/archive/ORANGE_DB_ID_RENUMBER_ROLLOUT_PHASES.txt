ORANGE — خطة مراحل: إعادة ترقيم id (1، 2، 3… بلا فراغات)
================================================================================
Archive: docs/archive/ORANGE_DB_ID_RENUMBER_ROLLOUT_PHASES.txt
قرار المالك (2026-06-02): **(ب)** كل سجل قديم يُعاد ترقيمه **1، 2، 3…** بلا فراغات، **مع** تحديث كل المفاتيح الأجنبية المرتبطة — **ليس** ضبط `AUTO_INCREMENT` فقط.
مرجع اللقطة الفعلية من السيرفر: **`D:\orange\scripts\orange_db.sql`** (mysqldump حي — يُحدَّثه المالك عند كل مراجعة).
SQL للتنفيذ على السيرفر: **`D:\orange_sql_updates.sql`** (خارج الريبو، آمن لإعادة التشغيل) — انظر `.cursor/rules/orange-php-utf8-workflow.mdc`.
Last updated: 2026-05-20 (إغلاق مرحلة 4 — ترحيل PHP v87 — الخطة كاملة)

**للوكلاء:** لا تُنفَّذ كل المراحل دفعة واحدة. بعد إغلاق مرحلة حدّث جدول «0) ملخص الحالة» و«آخر تنفيذ». نسخة احتياطية كاملة **قبل** أي مرحلة.

================================================================================
0) ملخص الحالة
================================================================================

| المرحلة | العنوان                              | الحالة   | ملاحظة |
|---------|---------------------------------------|----------|--------|
| 1       | إعداد / واجهة / دول / سنوات مالية    | **مغلق** | PHP: php_db_id_renumber_phase1_v84 (+ SQL مرجع phase1) |
| 2       | مقاسات وقوالب + أدلة استرشادية       | **مغلق** | PHP: php_db_id_renumber_phase2_v85 · includes/db_id_renumber.php |
| 3       | قواعد GL مساعدة + أنواع قيود        | **مغلق** | PHP: php_db_id_renumber_phase3_v86 |
| 4       | تشغيل ثقيل + دليل حسابات إن لزم     | **مغلق** | PHP: php_db_id_renumber_phase4_v87 |

**خارج النطاق (قرار مالك):** خيار **(أ)** — `AUTO_INCREMENT = MAX(id)+1` فقط دون إعادة ترقيم الصفوف القديمة.

**نتيجة مراجعة اللقطة (2026-06-02) — `accounts`:** 250 صفاً، `id` من **1** إلى **250** **بلا فراغات** → **مرحلة 4 لـ `accounts` غالباً غير مطلوبة** ما لم يتغيّر السيرفر بعد اللقطة.

================================================================================
1) قواعد التنفيذ (إلزامية)
================================================================================

1. **ترتيب:** مرحلة 1 → 2 → 3 → 4. لا دمج مراحل في commit/SQL واحد إلا بموافقة مالك صريحة.
2. **لكل مرحلة:** نسخة احتياطية → SQL على نسخة تجريبية إن أمكن → تنفيذ على السيرفر → تحقق (عدد صفوف، FK، عيّنة شاشات أدمن/متجر).
3. **إعادة الترقيم:** جدول mapping قديم→جديد ثم `UPDATE` لكل الجداول التي تشير إلى `id` (بحث في المخطط + `orange_db.sql`).
4. **بعد كل جدول:** `ALTER TABLE … AUTO_INCREMENT = (SELECT MAX(id)+1 …)`.
5. **نشر تلقائي (قرار المالك):** `git pull` ثم **أحد** المسارات:
   - أي صفحة تشغّل `orange_catalog_ensure_schema()` (الترحيل يبدأ **قبل** بوابة APCu)، أو
   - `php scripts/run_db_id_renumber_phases.php` على السيرفر (CLI)، أو
   - `health.php?key=…&rollout=db-id-renumber` (ثم `orange_run_migrations` لمزامنة `orange_schema_meta`).
   علامات v84–v87 مرة واحدة. إن بقي `orange_schema_meta=77` والكود أحدث: السيرفر لم يُحدَّث بـ `git pull` أو لم يُشغَّل أي مسار أعلاه.
6. **لا** تُضمَّن dumps كاملة أو أسرار في Git. SQL يدوي اختياري في `orange_sql_updates.sql` على **D:**.
7. **أداة تحليل محلي:** `scripts/analyze_id_gaps.ps1` (قراءة `orange_db.sql` — ليس بديلاً عن فحص السيرفر بعد التنفيذ).
