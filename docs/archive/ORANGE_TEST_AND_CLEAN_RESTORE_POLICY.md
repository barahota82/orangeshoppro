## الفصل بين ما يبقى وما يزال

- يبقى: الدول واللغات ومناطق التوصيل والإعدادات وشجرة التصنيف ودليل الحسابات والأرصدة/البيانات الأساسية المعتمدة، وأي قرار دائم أقره المالك. تُحدد القائمة من الواقع، ولا يساوي صفر المنتجات نظافة جميع الجداول.
- مؤقت: المنتجات والمتغيرات والعملاء والطلبات والفواتير وحركات المخزون/الحسابات والطوابير والصور التي أُنشئت خصيصاً لجولة الاختبار، وما ثبت ارتباطه بها. تحمل علامة جولة مميزة مع تسجيل IDs الفعلية في سجل خاص؛ لا تعدل Schema لإضافة وسم بلا حاجة.
- بيانات أعمال حقيقية أو مجهولة التصنيف: تُحفظ، ولا تُمحى لاستكمال تجربة أو إرجاع قاعدة قديمة. يظهر التعارض للمالك مع إجراء تعافٍ يحفظها.

## نقطة البداية قبل الكتابة

1. احصر الإعدادات والبيانات المطلوب الاحتفاظ بها، وحالة الجداول المرتبطة بالاختبار. لا تفترض أن النسخة الحالية نظيفة أو أن نسخة قديمة تصلح للجولة الجديدة.
2. نسّق كاتباً واحداً ونافذة اتساق؛ تحقق من انتهاء الكتابات والمهام ذات الصلة، ولا تعتمد الساعة أو MAX/COUNT وحدهما. لا Stop Pool افتراضي أو تغيير وصول الجمهور؛ تختار آلية السكون المناسبة للعملية المحددة.
3. أنشئ نسخة أساس حديثة تشمل DB وuploads عبر المسار القائم. تُحفظ على الاستضافة في موضع خاص خارج DOCROOT/Git وتُحمى فعلياً من التنظيف الدوري. لا يكفي افتراض احتفاظ دائم؛ retention الافتراضي بالمصدر 30 يوماً، ولا زر pin عام مثبت.
4. سجّل معرف النسخة، الموضع الخاص، وقت الكويت، الحجم والبصمات/manifest، قاعدة الهدف، commit الكود وإصدار المخطط، نتيجة health/فك الجرد، اتساق المصدر، وخطة الاستعادة. لا تكتفِ بملف غير فارغ أو رسالة نجاح.
5. تحقق من قابلية الاستعادة وفق ORANGE_RESTORE_OWNER_POLICY.txt ومسار staging/التحقق القائم قبل الاعتماد على النسخة. أي دليل ناقص يبقيها CREATED_UNVERIFIED. النسخ التاريخية لا تتحول تلقائياً إلى نقطة رجوع معتمدة.

## حالة الجولة وسجلها

| الحقل | المطلوب |
|---|---|
| round_id / owner / writer | معرف ثابت للجولة وكاتبها؛ لا كتابتين متزامنتين. |
| baseline_state | NOT_CREATED أو CREATED_UNVERIFIED أو VERIFIED_CLEAN أو RETIRED، مع سند كل انتقال. |
| backup_identity | اسم/موضع/وقت/حجم/بصمة؛ محتوى النسخة لا يغادر الاستضافة. |
| code_and_schema | commit وإصدار/علامات المخطط وقت النسخ والتجربة والرجوع. |
| retention_protection | آلية الحماية المثبتة، وحدود صلاحيتها وإعادة التحقق عند الاستئناف. |
| retained_settings | ما يبقى دائماً والتغييرات الدائمة التي تمت أثناء الجولة. |
| test_effects | معرفات السجلات والملفات والصور والطوابير وحركات المخزون/GL المتصلة؛ دون أسرار في الأرشيف. |
| runtime_effects | pause flags والكاش وجلسة السلة والمهام/الاتصالات الخارجية ذات الصلة. |
| last_safe_action / next_action | آخر إجراء مكتمل بالدليل، التالي المأذون، وما توقف وسببه. |
| restore_authorization | النسخة والنطاق والآثار المعروضة وموافقة المالك عند الاستعادة/الحذف الفعلي. |
| cleanup_verification | غياب بيانات الجولة وآثارها وبقاء الإعدادات والمخطط السليم والاستقبال الطبيعي. |

## تنفيذ التجربة

بعد VERIFIED_CLEAN: يجري الوكيل سيناريوهات الشركة والعميل عبر الواجهات/API المعتمدة، ويسجل المتوقع والفعلي والدليل والأثر بعد كل عملية. لا إدخال SQL عشوائي لتجاوز التحقق، ولا رسائل واتساب/بريد أو مدفوعات حقيقية بسبب تجربة افتراضية. عند timeout افحص وجود الكتابة قبل إعادة الإرسال. أبقِ تقارير التجربة وأدلة الأخطاء في الأرشيف حتى بعد تنظيف البيانات. إصلاح العيب مستقل عن اعتماد نجاح الاختبار؛ لا إعلان اكتمال من HTTP200 أو غياب خطأ pause فقط.

## الرجوع قبل بدء العمل الحقيقي

عندما يقرر المالك انتهاء الجولة: اعرض النسخة الدقيقة ونطاق الرجوع والبيانات التي ستزال والدائمة التي ستبقى، ثم احصل على موافقته عند الاستعادة الماسحة أو الحذف الفعلي. تحقق من عدم وجود أعمال حقيقية/إعدادات دائمة غير محفوظة ومن توافق المخطط والكود. عند الشك لا تُستعد DB أقدم؛ تُحفظ البيانات ويختار تعافٍ مناسب مع المالك. تُؤمّن الحالة الحالية وفق إجراء الاستعادة قبل تنفيذها، وتبقى كل النسخ على الاستضافة.

الرجوع يشمل DB والملفات المرتبطة عبر آلية مدروسة؛ لا يُحذف uploads بالكامل أو تُشغّل TRUNCATE/DELETE عامة أو أداة reset قديمة. افحص بعد الرجوع المنتجات والطلبات والعملاء والمتغيرات والمخزون/الحسابات والطوابير والمرفقات التي شملتها الجولة، وسلامة الإعدادات والروابط والترقيم بحسب الحالة المعتمدة. افحص runtime/pause والكاش والجلسات والاستقبال؛ DB+uploads وحدهما لا يعيدان كل حالة تشغيل. لا تُسجل CLEAN_VERIFIED قبل الأدلة، ولا تُعلن القاعدة بلا أي سجل لأن جداول الإعدادات والعلامات والسجلات النظامية قد تبقى بشكل صحيح.

## العمل لعدة أشهر

لكل جولة نقطة بداية حديثة؛ تُفصل التغييرات الدائمة عن بيانات الاختبار وتُطبق على الحالة النظيفة بمراجعة قبل اعتماد baseline جديد. أي تغيير Schema أو ترحيل يوجب مراجعة توافق الرجوع، ولا يُرجع Schema قديم فوق كود أحدث عشوائياً. يمنع اعتماد baseline أُخذ أثناء وجود بيانات تجربة غير مصنفة أو إهمال حماية النسخة من retention. انتهاء/انقطاع الجلسة ليس إذناً لتنظيف أو استعادة تلقائية.

ممنوع على الوكيل فتح/قراءة `.env.php` أو استخراج كلمات مرور. ممنوع تنزيل نسخ الاستضافة أو نسخ محتوياتها للأرشيف/الريبو؛ يسجل metadata والأدلة غير السرية فقط. نظام النسخ الحالي يؤرشف DB وuploads، ولا يضم `.env.php` الجذري؛ تشغيل التطبيق بإعداداته لا يساوي كشفها للوكيل.
