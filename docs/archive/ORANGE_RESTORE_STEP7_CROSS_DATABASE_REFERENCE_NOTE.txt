Classification: FALSE_POSITIVE_SQL_REFERENCE_PARSER

Authoritative Backup `php_pdo` dumps embed `SHOW CREATE TABLE` output containing
unquoted decimal defaults (e.g. DEFAULT 0.0000) and may include unquoted decimal
INSERT literals. The SQL tokenizer represents those as ident.dot.ident.

The Restore-only private cross-database scan previously treated every such shape
as a foreign schema reference, yielding STEP7_SQL_DUMP_CROSS_DATABASE_REFERENCE
before import start (execution_started=false).

Repair (Restore-only; Phase-2B.1 staging policy unchanged)
---------------------------------------------------------
`orange_restore_private_sql_scan_cross_database_refs` now:
1) skips purely numeric ident.dot.ident pairs;
2) requires the same object-name context gate as Phase-2B.1
   (`orange_restore_sql_is_schema_qualified_object_context`).
3) the shared object-name gate covers DDL/metadata object contexts such as
   CREATE INDEX ... ON db.table and CREATE/ALTER/DROP VIEW db.view.

Real external / system schema object references remain rejected.
